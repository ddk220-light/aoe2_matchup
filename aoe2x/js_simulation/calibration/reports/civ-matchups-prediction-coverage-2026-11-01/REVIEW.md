# Common-opponent winner prediction audit

This is an offline prediction audit for the phase-024 civilization-matchup checkpoint. It runs no fights and writes nothing to the frozen campaign. Ranking survivor-HP margins from the original engine are **features only**. Completed corrected-engine civilization fights are the labels. A provisional guess is neither an observed result nor an accepted inferred result.

The target is at least half of the 53,301 unresolved profile pairs in the phase-024 checkpoint (26,651 pairs), without treating close fights as decisive. A fixed temporal split trains on phases through 020, chooses benchmark rules on phases 021–022, and holds phases 023–024 aside for evaluation. The current engine's full-health attack-versus-armor damage matrix is also exported as a predictive feature for the granular model; it is not a simulated fight.

The first interpretable rule set chose two shared ranking benchmarks for each of eight matchup families. It required A's survivor-HP margin over B's to have the same sign and clear the family threshold against both benchmarks. Its phase-023/024 test called 120/120 selected fights correctly and proposed 4,964 guesses (9.3% of unresolved). Phase 025 was a new prospective check: 61 of 62 selected calls were correct, while Tatars Champions versus Berber Elite Genitours finished close. The skirmisher label had hidden a fast mounted subtype.

The second rule set narrows only militia-versus-skirmisher to foot skirmishers (`unit_class=0`). It keeps the other seven rules. It selects 4,937 unresolved pairs; 118/118 phase-023/024 calls were correct. Rechecking phase 025 selects 60/60 correctly. Because the foot-skirmisher condition was added **after** the phase-025 failure, that recheck is a screen, not independent prospective proof. Later reviewed phases must supply new independent evidence. The failure and both rule versions are preserved in the corresponding audit and validation JSON files; each rule has a stable condition hash. The compressed candidate list marks every row `prediction_only_not_an_observed_or_inferred_result`.

These interpretable rules alone do not meet the 50% target. The granular model evaluates survivor-HP gaps against all ranking benchmarks, completed common-opponent fights, relevant armor and attack classes, actual 27-unit cost-balanced counts, one-hit damage, attack timing, range, speed, accuracy, projectile count, and close-fight risk. Its audit and provisional prediction file are separate from the benchmark rule files. Any policy used to skip future fights must pass independent later phases and compatible V2 exact replay; a provisional model probability does not meet that gate.

The compute-bounded granular fit uses 60 histogram-boosting iterations with 63 bins and 96 extra trees. At 95% selected-winner confidence, ExtraTrees proposes 19,904 pairs, with 0 wrong/close calls among 138 calibration, 151 held-out, and 70 phase-025 selected fights. Histogram boosting proposes 27,800 but calls 8/195 calibration, 1/244 held-out, and 1/104 phase-025 selected fights incorrectly or decisively when close. The held-out and phase-025 mistakes are concentrated in Scorpion and archer–gunpowder contexts, so the candidate pool abstains from histogram boosting in those contexts while retaining the benchmark and extra-tree evidence there. The remaining histogram-boosting **calibration errors still require inspection**; this branch of the pool is not verified.

The resulting policy has **28,174/53,301 provisional guesses (52.86%)**, with no conflicting selected methods. A phase-025 screen calls 107/107 correctly, but that screen is not independent of the context guard chosen after inspecting phase 025. Phase 026 already contains 133 of these candidates and can supply a new reviewed check. `fifty-percent-candidate-guesses.jsonl.gz` keeps the winner, selected methods, confidence or benchmark keys, and a prediction-only status for each pair. The pool is an optimization hypothesis, **not a run-skipping list or completed matchup table**.

The Scorpion and archer–gunpowder guards were chosen after seeing phase-023/024 test mistakes as well, so a zero-error recount on those phases would also be a *screen*, not independent confirmation of the final policy. Phase 026 is the first untouched phase for this combined pool. The original model thresholds and mistakes remain in `granular-model-audit.json` for that reason.

`fifty-percent-candidate-guesses.jsonl.gz` is the archived **v1** pool. A second inspection found four remaining HGB calibration mistakes after the Scorpion guard: two close militia mirrors with *no shared ranking benchmark*, a close Imperial Elite Skirmisher versus fast, high-pierce-armor Rattan Archer, and a close Arbalester versus a 95-HP Hussar. The **v2** pool narrows only HGB's eligibility in those contexts. ExtraTrees and the two-benchmark rule can still propose winners in the same broad families. The exact excluded cases and per-split predictions are retained in `granular-calibration-predictions.json` and `granular-v2-guard-screen.json`.

The v2 pool proposes **28,013/53,301 profile pairs (52.56%)** and **40,340/77,441 unresolved displayed cells (52.09%)** in the frozen phase-024 matrix, with no conflicting selected methods. It still covers 27,800/52,902 (52.55%) of the phase-025 unresolved profile pairs. HGB alone selects 116/116 calibration and 205/205 phase-023/024 test fights correctly after these guards; ExtraTrees at 95% and the benchmark rules had zero errors on their own selected subsets. The v2 phase-025 screen selects 107/107 correctly. These guards were derived from calibration and previously inspected later fights, so none of those zero-error recounts certify the final combined policy. **Phase 026 contains 133 v2 candidate pairs and is the first untouched prospective test.** Compatible V2 replay is also still required before any accepted skip.

For the archived **v1** pool, expanding each profile pair to its civilization aliases gives **40,532/77,441 unresolved displayed cells (52.34%)** in the frozen phase-024 snapshot. The current **v2** count is 40,340 cells as recorded above. Both counts represent provisional guesses, not completed table coverage.

The reviewed-phase readers now require a completed phase review, the matching inference build, verified matrix and variant-file hashes, and an observed result for every nonblocked planned pair. A phase without a review raises an error rather than emitting a misleading zero-checked, zero-error report. Blocked candidates remain explicit in the denominator and set `completeForPlannedCandidates` to false. Eight regression tests cover these checks. The phase-025 source-checked screen still selects 107/107 pool predictions and 60/60 benchmark predictions correctly; it remains a post-hoc screen, not independent validation.
