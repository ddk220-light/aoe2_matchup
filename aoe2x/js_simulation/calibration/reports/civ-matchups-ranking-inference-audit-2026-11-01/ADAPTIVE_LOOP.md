# Versioned common-opponent selection loop

The phase-20 V3 snapshot has 55,910 unresolved distinct mechanics-profile pairs after the narrow v5c direct inference. Comparing each side's saved ranking results against the same standard opponents produces 8,304 tentative winners. Of these, 3,334 are within an effect and army-count context already supported by corrected-engine observations, and 3,330 were eligible before phase 020 for independent validation. The other 4,970 extrapolate an effect or count and remain ordinary simulation candidates.

The rule pack `civ-matchups-adaptive-rule-v1-2026-11-01` freezes unit-line-specific opponent sets and HP-margin gaps fitted through phase 019, plus hashes of its training-eligibility inventory. Original-engine ranking outcomes are features, not compatible measurements. A phase-020 dry run selected 64 prospective rule checks and 192 hard cases; it skipped **zero** fights. Although 29 phase-020 outcomes agreed with their common-opponent predictions in an initial audit, all 29 were outside the phase-019 supported-effect pool. The stricter prospective gate correctly counts zero eligible checks from that phase.

At each completed phase the selector rebuilds current inference from journals and rechecks each rule only on new profile-pair fights not used to fit it. The pair must have been eligible before the fight, have a supported effect and previously seen army-count shape, and have a complete observed seed set. One wrong winner or close fight called decisive disables the family and requeues its guesses. Promotion requires 60 independent correct profile-pair fights, at least 12 distinct profiles, and zero such errors. That sample gives a one-sided 95% binomial upper error bound of about 4.9% if its observations are representative. The selector spreads probes across profiles to reduce correlation. After promotion it keeps testing up to two predicted pairs per family per phase, so new counterexamples can revoke the rule.

Only a promoted rule in a supported context may skip a fight. Each skipped estimate is archived with its predicted winner, common-opponent evidence, frozen rule hash, source inference hash, and validation counts. It is never stored as an observed seed or assigned survivor HP. If a later check disables the rule, all unresolved skipped pairs reenter the run queue. The rest of each 256-pair phase prioritizes estimated downstream inference coverage per measured worker second, with family diversity and a durable phase plan. It recomputes possible R1/R2/R3 transfer gains from the latest table, scanning up to 600 high-connectivity candidates; if that read-only scan cannot finish in three minutes, it uses the frozen phase-020 priority report and records the fallback. Frozen physics, counts, seeds, journals, and the active phase plan do not change.

This V3 rule loop is a collection policy. Final use under the collision-repaired V2 engine still requires compatible V2 validation and a consistent V2 result table. Blocked or incomplete V3 seeds never become guessed losses. The offline phase-20 dry run ran no combat and has no effect on the current detached runner until the versioned selector is installed between phase plans.

Two repeatedly stalled geometry families are also held out of the ordinary V3 queue: Muisca Elite Guecha Warrior against Champions, and Mapuche Imperial Elite Skirmisher against heavy cavalry. The phase-20 inventory contains 33 and 17 unresolved profile pairs in those groups, respectively. This is only a scheduling deferral for separate V2-stream/pathing review; none receives a winner or a close conclusion. The selected 256 fights remain available without those 50 cases.
