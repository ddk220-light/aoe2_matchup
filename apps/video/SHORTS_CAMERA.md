## Animated story Short (2026-09-20)

`build_story_short.py` is an opt-in second stage, not a replacement for the
existing battle renderer. It consumes an approved `build_vertical_short.py`
output folder (including `manifest.json`, `camera.json`, `layout.png`, `short.mp4`)
and the referenced clean recording / verified HP timeline.

1. `prepare --battle <approved-folder> --output <new-folder>` exports
   `gameplay.mkv`: lossless 1080-square camera footage, no overlays, same frame
   count and timing as the approved battle.
2. Run the installed upstream SeedVR2 standalone CLI on that file. Use
   `--resolution 2160 --batch_size 9 --uniform_batch_size --temporal_overlap 1
   --chunk_size 72 --cache_dit --cache_vae --output_format png`, the approved
   7B Sharp model, LAB matching, seed 42, zero added noise, SDPA, CPU offloading
   for DiT/VAE/tensors and 512-pixel VAE encode/decode tiles (128 overlap).
   PNGs are written as `gameplay_000000.png`, etc., in the output's `gameplay`
   subfolder. The chunk context is removed by upstream, not by this compositor.
3. `render --battle <approved-folder> --output <same-new-folder>
   --seed-frames <enhanced-gameplay-folder> --victory-audio <decoded-victory.wav>` blends 75% Seed / 25% Lanczos
   source at 2160 square, downscales to the protected battle viewport, then composes the floating
   battle overlays described below. Model processing never includes the HP queues or
   stat cards; native in-game bars/notifications remain part of the recording.

Provide the usual FFmpeg-on-PATH and `AOE2_GAME_DIR` installation override.
The source run must have its matching `plan.json`, stats panels and verified
unit timeline. Attack animations default to the tracked
`graphics/units/<unit>/<unit>_attack_dir06_dat4x.gif` assets; `--attack-frames`
can select lossless PNG animation folders. Result ornaments
and Trajan font come from the installed game's existing comparison renderer.

The three-second opener contains looping attack animations, names and "Who wins?";
no HP queues or stat cards. In its final 0.6 seconds the upper/lower panels
ease outward to reveal the first battle frame. No combat is hidden under the
opener. The entire approved battle then plays. A result screen of up to five seconds
features whichever main army won, with that unit's name, civilization, attack
animation and victory ornament. Never show the losing top unit as "Defeated".
The full game-art background extends behind a website message, with no stat
cards or detailed footer on the ending. P4 buffer units never affect that result. The
whole-number HP percentage is relative to the **winner's entire starting army**

backing is alpha-composited at 140/255 opacity, keeping the background visible.
The game victory ornament is composed without its old narrow backing. The
existing comparison renderer keeps its original backing by default. An undecided
fight has no victory ending; this renderer reports that instead of inventing one.

## Current renderer and camera options

`build_vertical_short.py` retains the original fixed layout and HP timing. New
options affect gameplay only; the default remains `--camera fixed`.

- `--camera action`: automatically observe colored moving sprites in the video.
- `--camera telemetry`: decode living P2/P3/P4 positions from the archived
  `frames.bin`; calibrate world coordinates to recorded screen coordinates using
  unique HP-fraction matches in the existing verified alignment evidence.
- `--enhance-model /absolute/path/to/model.pth`: run a Spandrel-supported local
  super-resolution model on gameplay, then compose the untouched overlays.
  Requires CUDA PyTorch and Spandrel in the selected Python environment.

Both automatic camera modes produce **one-way smooth movement and zoom-in
only**. Telemetry holds the establishing shot until the first recorded main-army
HP loss. Horizontal travel targets the median main-fight center
and is capped at 40 source pixels, rather than chasing the final survivor;
vertical travel retains quintic easing toward the late-fight center. A
non-increasing future-bounds envelope sets zoom targets as the fight contracts,
with three smoothing stages for gentle acceleration and braking. A broad
mid-fight formation no longer prevents a tighter late-fight crop. The visual
action mode uses the same planner without a telemetry contact-time hold.
Unusual retreats may clip and should be reviewed separately. This policy is
deliberately not a camera that tries to keep every outlier visible at all costs.

Telemetry prerequisites: the archived stream, matching clean footage, and a
verified alignment with at least six unambiguous HP/position matches. A fixed
world-to-screen projection assumes the recorded game camera is settled; this is
not a generic moving-observer-camera tracker. If calibration is unavailable, the
command reports that requirement rather than silently inventing a projection.
The visual `action` mode is an explicit alternative.

P4 positions influence framing only while alive. They do not enter the main
armies' portrait queues or totals. HP timestamps and elimination trimming retain
their existing behavior. No game simulation or source recording is modified.

Example (with the usual video dependencies, game assets and FFmpeg configured):

```powershell
python apps/video/build_vertical_short.py <run-folder> --output <new-output-folder> --camera telemetry --enhance-model <model.pth>
```

Outputs include `camera.json` (observations, calibration, reproducible path),
`enhancement.json` when enabled, layout and frame previews, `manifest.json`,
`render.log`, and `short.mp4`.
