# CPU/GPU thermal monitor

Current operating instructions: [thermal monitoring and recovery](video-production/OPERATIONS_AND_RECOVERY.md#thermal-monitoring). The old Codex scheduled capture follow-up is paused by user request. Current capture/production wrappers check thermals every 15 minutes. The five-minute combined-heartbeat description below is historical and must not reactivate that automation. CPU readings remain unavailable under the user's existing continuation policy; do not report them as safe.

Requested by the user: check every 15 minutes and pause tasks when too hot.

The Codex app allows one active heartbeat per thread. Use the combined `liao-dao-recording-progress` heartbeat every five minutes, checking status.json timestamp and running the thermal guard only when 15 minutes have elapsed. This retains the user-requested 15-minute temperature cadence while production checks remain every five minutes. Run `apps/video/.venv/Scripts/python.exe apps/video/thermal_guard.py` from `C:/dev/aoe2/aoe2_matchup` when due. GPU is read live with nvidia-smi. CPU uses the maximum current core/package sensor value from the read-only Libre Hardware Monitor broker; snapshots older than 90 seconds are rejected. Missing sensors are reported, never interpreted as safe temperatures.

Thresholds: CPU >=90 C or GPU >=85 C. These are conservative operating choices below the i5-12600KF's 100 C Tjunction and RTX4070's 90 C maximum GPU specification. References: https://www.intel.com/content/www/us/en/products/sku/134590/intel-core-i512600kf-processor-20m-cache-up-to-4-90-ghz/specifications.html and https://www.nvidia.com/nb-no/geforce/graphics-cards/40-series/rtx-4070-family/ . This scheduled monitor supplements hardware protection; it cannot catch every spike between 15-minute checks.

The CPU reader uses official LibreHardwareMonitor 0.9.6, downloaded from its GitHub release into `.tools/thermal/lhm-0.9.6`. Its bundled PawnIO installer has a verified Authenticode signature from namazso.eu. Windows administrator approval is required for `apps/video/setup_thermal_sensor.ps1`, which installs the hardware-access driver if missing and starts `thermal_sensor.ps1` hidden under Windows PowerShell 5.1. The broker only reads CPU temperatures, publishes a fresh snapshot every five seconds, and has a mutex preventing duplicate instances. It does not change clocks, voltages or fans. It must be restarted after reboot. No startup task or system schedule is installed by these scripts.

`data/local/thermal/status.json` holds each thermal decision; `history.jsonl` is the temperature history. `PAUSED.json` is the persistent pause latch and exact process identity ledger. Every AoE2 production task must check this latch before starting/restarting work and must not clear it automatically.

On a confirmed threshold breach, the checker suspends AoE2DE_s.exe and this repository's Python, Node and FFmpeg workers, plus their child processes. This covers recordings, overlays, simulations, local production queues and their encoders. Windows system processes, unrelated applications, Codex itself and the thermal checker/broker stay active. PID creation times prevent suspending or resuming a reused PID. Existing suspended process identities are skipped so repeated checks do not stack suspend counts. Errors or interrupted `attempting` records require manual inspection, not a blind retry.

Notify the user when a thermal pause occurs, when any process could not be suspended, or when sensor readings become unavailable. Stay quiet for normal readings and unchanged states. Keep checking temperatures while paused. Never automatically resume, start replacement workers, or bypass the pause latch. On a thermal trip, skip the production part of the combined heartbeat but keep that heartbeat ACTIVE for temperature checks. Do not pause the combined automation, which would disable thermal monitoring. Other separate production automations, if any, may be paused through the app tool.

Resume only after the user explicitly asks and fresh CPU <80 C and GPU <75 C readings are available: `python apps/video/thermal_guard.py --resume`. Any game recording interrupted by a thermal pause must be reviewed/re-recorded before it is accepted; wall-clock recorder timeouts and gRPC alignment may span the pause. Completed artifacts remain intact. No process is killed and no machine power settings change.

Tests: `PYTHONPATH=apps/video;. python -m unittest apps/video/test_thermal_guard.py`. Tests cover exact thresholds, missing/stale CPU readings, unrelated-process exclusion and descendant inclusion. A disposable actual Python runtime also verifies suspension stops its file ticker and resumption restarts it. Venv launcher and runtime are separate processes; both are included in real workload selection.
