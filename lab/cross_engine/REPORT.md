# Cross-engine comparison — extracted JS engine vs `simulation_real.py`

Generated by `lab/cross_engine/compare.py`. READ-ONLY experiment: nothing in `aoe2x/`, `apps/`, `tools/` or `data/golden/` was modified to produce it. **Divergence is expected** — `docs/simulation-engine-migration.md` §6 documents six behavioural differences between these two engines (map size, spawn X, spawn jitter, collision radius, kite gate, crowd churn). This file maps where and how big the differences land; it draws no conclusion about which engine is right.

## Methods

16-unit roster (below), all **120 unordered pairs**, **10 v 10** units a side, seeds **1, 2, 3, 4, 5** = **600 fights per engine**. Team 1 = `a`, team 2 = `b` in both engines. Both engines are fed the SAME combat dicts (`combat_dicts.json`, built from `data/golden/aoe2_reference.db` age='Imperial' rows by `run_py.py`, same payload shape the webapp serves), so unit stats are identical and every difference below comes from the engines themselves.

**Caps.** JS: 600 game-seconds = 36000 ticks at 1/60 s, no wall-clock cap, no early exit; on running out with both sides alive `sim.winner` stays `null`. Python: 600 game-seconds = 18000 ticks at 1/30 s (`MAX_BATTLE_SECONDS`), wall-clock backstop disabled (`max_wallclock=None`) so results do not depend on the host; at the cap it declares a winner by HP%, and from 120 s (`KITE_DECISION_TIME`) it can also end a fight early as `kite_win` (decisive) or `stalemate` (winner 0, both sides alive).

**Winner normalisation** (the same four values on both sides; raw engine values are preserved in the JSON as `raw_winner` / `end_reason`):

| normalised | JS | Python |
|---|---|---|
| `a` | `winner === 1` | `winner == 1` (`eliminated` or `kite_win`) |
| `b` | `winner === 2` | `winner == 2` (`eliminated` or `kite_win`) |
| `draw` | `winner === 0` (mutual annihilation) | `winner == 0`, `eliminated`, both teams wiped |
| `timeout_both_alive` | `winner === null` — 600 s spent, both sides alive | `end_reason` `time_cap` (600 s) **or** `stalemate` (kite decision), both sides alive |

The Python's HP%-tiebreak at the 600 s cap is **discarded** in the normalised field, because the JS refuses to break that tie and scoring one engine's tiebreak against the other's abstention would manufacture disagreement. A sensitivity figure with the tiebreak honoured is given in §2. The Python's `kite_win` early exit IS kept as decisive, because the engine does declare a winner there; those fights are counted in §4.

**RNG.** The two engines use different RNG algorithms, so the same seed does NOT produce comparable draws. The comparison is therefore distributional: 5 seeds a pair, majority (3-of-5) winner, and means over all 600 fights.

**Metrics.** survivor margin `m = alive_a - alive_b` per fight, delta = `|m_js - m_py|` (0..20). HP% margin `h = hp_a/(10 x maxhp_a) - hp_b/(10 x maxhp_b)` per fight, living units only, delta = `|h_js - h_py|` in percentage points. Fight-time ratio = `t_js / t_py` in game-seconds. Majority winner = the value held by >= 3 of 5 seeds, else `split`. Two pairs agree when both engines produced a non-`split` majority and the majorities are equal.
